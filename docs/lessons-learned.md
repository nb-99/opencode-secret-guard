# Secret guard

Design notes live in [../secret-guard.md](../secret-guard.md). This file records
the mistakes made while building it.

## Path handling and gitignore

- **`opencode-ignore` broke every external path.** It rewrote absolute paths outside the project into `../../…` and then rejected them (`Invalid path format`), which is why reads into the agent-memory vault failed and why `glob`/`grep` silently dropped external hits. Replaced by `secret-guard`, which resolves each target's own repo root and defaults to *keeping* results it cannot classify.
- **A `git` subprocess costs ~11 ms, so per-result `check-ignore` does not scale.** The file-tool predicate batches with `git check-ignore -z --stdin` (one spawn per repository) and finds repo roots by walking up for `.git` instead of `git rev-parse`; 100 `grep` hits went from ~1.2 s to ~22 ms. A parity unit test pins the batch verdicts to the single-path ones.
- **`git ls-files -o -i --exclude-standard --directory` beats reimplementing gitignore.** It gives exact git semantics with directories collapsed, so there is no glob-to-regex translation to get wrong.

## sandbox-exec and SBPL

- **macOS sandbox rules match canonicalized paths.** A rule anchored on `^/etc/` never fires, because `/etc` is really `/private/etc`. Emit `realpath`'d paths, or use suffix/component anchors (`/\.env$`), which are symlink-proof by construction.
- **SBPL applies the last matching rule, but only within the same operation name.** `(allow file-read*)` does *not* override `(deny file-read-data)` — an allow must repeat the exact operation list of the deny it is meant to beat. Verified empirically; getting this wrong silently disables every exception.
- **Deny `file-read-data`, not `file-read*`.** `file-read*` includes metadata, so denying it makes `ls -la` print `Operation not permitted` for every secret in the directory. Denying only the data read hides contents while leaving `stat` intact.
- **Express ignored *directories* as a `^<dir>/` regex, not `(subpath …)`.** A subpath deny also blocks `readdir`, so `find` errors on every ignored directory. Filenames are not secret; their contents are.
- **A `^<dir>/` prefix deny still blocks `readdir` on every *sub*directory.** Enumerating a directory is a `file-read-data` operation on that directory, whose path matches the prefix — so tree walkers (eslint, `find`) hit `EPERM` one level into an ignored tree. The fix is to re-allow each directory below the tree as a `(literal …)` after the deny; a file path never equals a directory literal, so contents stay denied.
- **`sandbox-exec` refuses to apply a profile inside an existing sandbox.** The kernel secret-guard tests therefore cannot run from an agent shell; both entry points now probe and exit 2 with an explanation. Run `nix run .#integration` from a plain terminal.
- **Sandboxing does not scrub inherited environment variables.** Shell-init secrets remain readable through `printenv` unless they are explicitly removed before launching the sandbox. `secretEnvironment` is the source of truth for that denylist; MCP servers keep their independently configured credentials.

## The command scanner

- **A relaxation group needs *every* command segment to belong to it.** `cd repo && git commit` used to fall back to strict and fail as `gpg: keyblock resource ~/.gnupg/pubring.kbx: Permission denied` — an error naming neither the guard nor the cause. Segments that cannot open a file are now skipped: `cd`/`pushd`/`popd`/`echo`/`printf`/`true`/`false`/`:` always, and `cat`/`head`/`tail`/`wc`/`sort`/`uniq`/`tr`/`nl`/`rev`/`column` when every argument is a bare number or a path-free flag. A **heredoc** still forces strict, because the segment scanner splits on newlines and reads the body as commands. Write payloads to a file instead of piping a heredoc into a credential-using command.
- **A rule that is right for a simple command is usually wrong for a compound one.** Three separate guard bugs were the same shape: `^<dir>/` denies were right at the top of a tree and wrong one level in; the group rule was right for `git commit` and wrong for `cd && git commit`; the `&` separator was right for `a & b` and wrong for `2>&1`, which it split into a phantom segment named `1` and forced strict. When adding a rule, state the compound case it must survive, and test it.
- **Verify shell parsing against `/bin/zsh`, not intuition.** `>& word` looks like it hides a command, but zsh writes both streams to a *file* named `word` — nothing after it is executed. One `zsh -c` in a temp dir settles what a static scanner may safely assume.
- **A guard pattern must respect quoting, or it fires on prose.** The opaque-construct scan matched the raw command, so `` git commit -m "fix `2>&1`" `` ran strict — and so did `git push origin source-maps`, because `\bsource\b` treats `-` as a word boundary. The scan is now quote-aware, and `eval`/`exec`/`source`/`.` are no longer matched as text at all: they only execute when leading a segment, where they are already the segment's binary and belong to no group. A pattern that duplicates a structural rule keeps only its false positives.
- **Shell expansion syntax is an execution surface, not just interpolation.** zsh adds `=(...)`, `${(e)...}`, and executable glob qualifiers such as `*(e:cmd:)`; all must force strict just like `$()` and `<(...)`. Leading environment assignments force strict too, because variables such as `GIT_SSH_COMMAND`, `GIT_EXTERNAL_DIFF`, and `RIPGREP_CONFIG_PATH` can inject commands or hidden file-reading options into an otherwise trusted binary.
- **A pipe out of a credential binary is a group-coverage question, not a deny bug.** `kubectl get crd | rg x` failed with `operation not permitted` on `~/.kube/config` because `rg` was in no relaxation group and the resolver is all-or-nothing per command; `2>/dev/null` on an earlier segment made the *second* error the visible one. `rg`, `grep`, and `jq` are pattern-first filters, but they are skippable only as direct pipe consumers with exactly their pattern/filter operands. File operands, recursive/files modes, leading environment assignments, and path-bearing flags (`-f`/`--file`, `--ignore-file`, `--pre`, `--exclude-from`, jq `--slurpfile`/`--rawfile`/`-L`) keep the command strict. This conservative boundary prevents parent-directory traversal, cwd changes, symlink following, config-file option injection, and `--` operand ambiguity from exposing a relaxation directory. `sed`/`awk`/`tee`/`xargs` stay strict because their scripts or operands can name files the scan cannot see. To search credential-command output, write it to `/tmp/agent-temporary-workspace/` in one shell call, then search the file in a second call.
